## 1. 愿景与概述

**UniPass** 是一个面向 Web3 的匿名真人身份层（Proof-of-Personhood, PoP）。  
我们利用“电子护照 NFC + 零知识证明 (ZKP)”的组合，解决“如何证明我是独特真人”与“如何保护我的隐私”这对矛盾。

- **一次验证，终身匿名**：持有电子护照的任何人，只需在本地完成一次离线扫描 + ZK 证明，即可获得永久有效的匿名身份承诺。
- **DApp 即插即用**：开发者只需调用一个合约接口，便能验证“用户是真人”且“未重复参与”，无需 KYC、无需收集隐私数据。
- **完全隐私**：护照原始数据不出本地、不上链；不同 DApp 间的匿名身份互不关联。

一句话愿景：**做 Web3 世界的“匿名通行证”，只需要一本护照。**

## 3. 用户旅程

### 3.1 一次性注册（Setup）

1. **打开支持 UniPass 的钱包 / App**  
2. **NFC 扫描护照**：通过 ZKPassport SDK 读取芯片并验证政府签名。  
3. **生成匿名身份**：本地生成随机私钥 `IdentitySecret` 与承诺 `IdentityCommitment`。  
4. **生成 ZK 证明**：证明“我拥有有效护照 + 对应此承诺”。  
5. **写入链上匿名池**：将承诺插入 UniPass Registry（Merkle Tree），同时护照内容永不上链。  

### 3.2 任意多次使用（Usage）

1. 用户在任意 DApp（空投、治理、社交）选择 “Verify with UniPass”。  
2. 钱包提示授权，用户确认。  
3. 本地基于 `IdentitySecret` 与 DApp 的唯一标识生成新的零知识证明。  
4. DApp 合约验证证明并检查 Nullifier 是否已使用，若没有则放行。  
5. DApp 只知道这是“匿名真人池中的某人”，却无法追踪其真实身份或跨应用行为。

## 4. 技术架构

### 4.1 组件

1. **ZKPassport SDK**：验证护照芯片签名，输出可信的“真实人”证明。  
2. **UniPass Registry (智能合约)**：维护全球匿名真人池（Merkle Tree），并为 DApp 提供 Nullifier 去重逻辑。  
3. **Semaphore Verifier**：零知识证明验证层，确保用户在不同 DApp 间的匿名性。  

### 4.2 密码学流程

**注册：**

1. 用户本地生成随机数 `s` 与 `r`，计算 `C = PoseidonHash(s, r)`。  
2. 生成 `ZKPassport` 证明 `π_passport`，声明“我拥有有效护照并请求写入承诺 C”。  
3. 合约验证证明、插入 Merkle Tree。  

**DApp 验证：**

1. 访问 DApp `Addr_A` 时计算 Nullifier：`N = PoseidonHash(s, r, Addr_A)`。  
2. 生成证明 `π_app`，证明 `(s, r)` 属于 Merkle Root 且 Nullifier 计算正确。  
3. DApp 合约 / Registry 验证证明，并确保 `N` 未被使用，完成真人校验。

## 6. 当前实现概况

本目录提供了以下基础模块，方便继续开发：

- **智能合约 (`contracts/`)**  
  - `UniPassRegistry`：依赖 `@semaphore-protocol/contracts`，负责接入护照验证器并维护全球匿名池。  
  - `MockPassportValidator`：用于本地测试的简易护照验证器。  
  - 完整 Hardhat 配置、TypeScript 测试。

- **SDK (`sdk/`)**  
  - TypeScript 草案，包含身份生成、Nullifier 计算、与钱包交互的基础骨架。  

- **文档 (`docs/`)**  
  - 本白皮书草案，可直接扩展为 Pitch Deck 或技术规格说明。

5. **监管与合规**：在不牺牲隐私的前提下，提供可选的审计线索与撤回机制。

## 8. 结语

UniPass 不试图重新发明身份，而是连接 **最普及的护照标准** 与 **最先进的隐私原语 (Semaphore)**。  
它使得真人验证像调用 API 一样简单，同时让用户掌控自己的隐私主权。  
我们期待与钱包、DApp、基础设施伙伴一起，将“匿名真人层”打造成 Web3 的默认公共设施。
